# Token 成本控制

## 目标

Token 成本控制用于在提高代码质量的同时，避免上下文消耗失控。

## 默认策略

- 默认单 Agent。
- 默认读取极薄入口、当前 Agent 协作层路由、必要项目记忆源和相关代码。
- 默认不读取历史长文档。
- 默认不启用多 Agent。
- 默认不全仓扫描，除非任务需要。
- 老项目升级默认原地换芯，只提取有效项目记忆，不长期保留旧 Agent 协作层文档。
- 完整方案默认先生成结构化摄取记录，不作为后续任务默认全文上下文。
- 完整方案落地默认读取方案落实台账，不回读原始讨论全文。
- 微小变更默认走 S0 轻量模式，不读取无关项目记忆、项目风格画像和长文档。
- 微小变更默认在主工作区完成，不默认创建 Git worktree（工作树）；多任务并行、大改造、长期任务或冲突风险明显时才启用独立工作树。

## 预算分级

| 等级 | 适用场景 | 上下文策略 |
|---|---|---|
| S0 | 微小样式、文案或局部无业务变更 | AGENTS + 相关文件 + 最小验证 |
| S | 小修小补 | 入口 + 相关文件 |
| M | 普通功能或 Bug | workflow + 模块卡片 + 相关代码 |
| L | 跨模块任务 | 增加架构、业务摘要、测试 |
| XL | 复杂排查或重构 | 深读历史问题，必要时启用多 Agent |
| ADOPT | 老项目原地换芯 | 极薄入口 + 旧 Agent 协作层清退 + 项目记忆源提取 |
| INTAKE | 完整方案摄取 | 方案全文一次性理解 + 结构化索引 + 系统影响矩阵 |
| PLAN | 完整方案落地 | confirmed / active 台账 + 相关模块和业务上下文 |
| PARALLEL | 多 Codex 任务并行开发 | 变更分级 + parallel-worktree workflow + 独立工作树生命周期记录 |

## 升级条件

只有出现以下情况才升级上下文：

- 文档和代码冲突。
- 复现路径不清。
- 涉及多个模块或多个业务对象。
- 涉及历史复发问题。
- 涉及数据、权限、安全或不可逆操作。
- 老项目升级后，具体任务首次触达迁移出的项目记忆源。
- 方案摄取后，具体任务首次触达方案影响的模块、业务对象或接口。
- 完整方案开发时，台账包含多个任务、多个模块或多个验收口径。
- S0 修改触发业务规则、字段、状态、接口、权限或模块边界变化。
- S0 修改触发项目风格、端侧习惯或工程约定变化。

## 成本报告

复杂任务最终报告应说明：

- 读取了哪些入口、项目记忆源、代码或文档。
- 为什么需要深读。
- 是否启用了多 Agent。
- 是否存在可优化的上下文入口。
- 是否读取旧 Agent 协作层或历史文档；如果读取，说明触发原因。
- 是否读取方案全文；如果读取，说明为什么不能只读摄取索引。
- 是否读取方案落实台账；如果没有读取，说明为什么任务不来源于完整方案。
- 本次变更等级；如果是 S0，说明为什么不需要项目记忆源同步。
- 本次工作区模式；如果创建了 Git worktree，说明路径、分支和清理状态。
